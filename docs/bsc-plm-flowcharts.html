01

MTM new fabric · from the ask to live, every touch point

The longest path in the business, with its two starting points: design logs one concept — "we need this new fabric", with the working name, the why, the book it fills, when it is wanted and the reference — and it is sampled before any cloth is bought; or design reads a gap in a book and raises a request for several options at once. Both arrive at the same place: sourcing puts one vendor against each, design pushes the PO, and from there the cloth has one record all the way to a customer ordering it.

One option · every state it can be in

The smallest decision in the system, drawn completely. Three status words are the only ones anyone reads: sourcing to add vendors · design to push PO · extension asked.

  open : sourcing to add vendors
  open : (vendor card empty · form open)
  withDesign : design to push PO
  withDesign : (one vendor · Push PO · Reject · More time)
  extension : extension asked
  extension : (sourcing — Extend · back to design · withdraw)
  poRaised : PO raised
  poRaised : (fabric on the master · FPO · incoming)
  closed : closed
  closed : (reason kept · reopen)

  open --> withDesign : Send to design
  open --> open : Add / Edit vendor (replaces, history kept)
  withDesign --> poRaised : Push PO · metres
  withDesign --> open : Reject (reason) — last vendor out
  withDesign --> extension : More time
  extension --> withDesign : Hold extended — back to design
  extension --> open : Mill won't hold — withdraw vendor
  withDesign --> closed : Close option
  open --> closed : Close option (design or sourcing)
  extension --> closed : Close option
  closed --> withDesign : reopen (live vendor)
  closed --> open : reopen (no vendor)
  poRaised --> [*]

Every arrow is a button one person presses. An option that has a PO cannot take a new vendor; a rejected vendor cannot be pushed; closing and reopening keep the reason.
